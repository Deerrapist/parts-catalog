# Этап 2. Go-сервер в контейнере

Состояние: parts_backend поднят, GET /health отдаёт 200 и
{"status":"ok"}. К базе НЕ подключён — намеренно.

## Решения
- Этап разделён: сначала сервер без БД, потом подключение.
  Иначе при ошибке непонятно, где она — в сборке, в сети между
  контейнерами или в SQL.
- Multi-stage build: в builder-слое компилятор и исходники (сотни МБ),
  в финальный копируется только бинарник (~20 МБ).
- go.mod/go.sum копируются отдельно и раньше остального кода —
  Docker кеширует слой зависимостей, при правке main.go они
  не скачиваются заново.
- CGO_ENABLED=0 — статический бинарник, иначе собранное
  в golang:alpine может не запуститься в чистом alpine.

## Грабли
- r.Run("0.0.0.0:"+port), НЕ localhost. Внутри контейнера localhost —
  это сам контейнер, снаружи сервер недоступен, проброс порта
  не спасает. Выглядит как "контейнер работает, но connection refused".
- apt install golang-go даёт Go 1.21, а Gin требует >= 1.25.
  Ставится тарбол с go.dev.
- Мажорная версия в Dockerfile должна быть >= директивы go в go.mod.
  Иначе сборка падает на go mod download.

## Проверено
curl -i localhost:8080/health → 200 OK, {"status":"ok"}
Из браузера Windows тоже отвечает (проброс порта WSL работает).
