# Этап 1. База в контейнере

Состояние: postgres:16-alpine healthy, схема накатана, INSERT/UPDATE
проверены, версионирование работает.

## Решения
- version (sequence) вместо updated_at (timestamp): устойчив к
  рассинхрону часов между сервером и клиентом.
- deleted_at вместо DELETE: офлайн-клиент иначе не узнает об удалении.
- UUID вместо serial: клиент сможет создавать записи офлайн без коллизий.
- Триггер BEFORE UPDATE, не AFTER: в AFTER строка уже записана,
  присваивание NEW.version ни на что не влияет.

## Грабли
- DEFAULT nextval() срабатывает ТОЛЬКО на INSERT. Без триггера правки
  и soft delete не попадают в дельту — тихая потеря данных.
- init.sql выполняется только при пустом volume. Правишь схему →
  docker compose down -v, иначе изменения не применятся.

## Проверено
UPDATE поднял version 1 → 3, строка ушла в конец ORDER BY version.

## Непонятно / вернуться
- Гонка при конкурентных записях: nextval() выдаётся до COMMIT,
  порядок коммитов может не совпасть с порядком версий. Разобрать
  перед Фазой 2 — это материал для текста УПД.
