# Этап 3. Сервер ↔ база, полная выгрузка

Состояние: GET /api/v1/parts отдаёт весь каталог. Реализация
подхода №1 — база сравнения для дельта-синхронизации.

## Решения
- DB_HOST=postgres (имя сервиса), не localhost: внутри docker-сети
  у каждого контейнера свой сетевой стек, localhost для backend —
  это он сам. Compose поднимает DNS по именам сервисов.
- depends_on + condition: service_healthy. Без healthcheck ожидание
  только по факту запуска процесса, а Postgres принимает соединения
  на несколько секунд позже.
- Пароли в .env (в .gitignore), .env.example коммитится как шаблон.
- ORDER BY version — не для дельты, а для воспроизводимости замеров:
  без явной сортировки порядок строк не гарантирован и размер JSON
  гуляет между прогонами.
- WHERE deleted_at IS NULL в полной выдаче. В дельте семантика будет
  обратной: удалённые ОТДАЮТСЯ с флагом, иначе клиент не узнает
  об удалении.

## Грабли
- sql.Open не подключается к базе, только готовит пул соединений.
  Реальная проверка связи — db.Ping().
- nil-слайс сериализуется в JSON как null, пустой — как [].
  make([]Part, 0) вместо var parts []Part.
- Nullable-колонки требуют указателей (*string, *int) — обычный
  string не примет NULL, Scan вернёт ошибку.

## Наблюдение для текста
UUID id + category_id = 72 байта на запись при полезной нагрузке
~150 байт. Идентификаторы занимают порядка трети объёма ответа.
Измерить точно на этапе замеров (UUID vs bigint).

## Перед этапом 4
Gin работает в debug-режиме — логирует каждый запрос, это войдёт
в измеряемое время. Перед baseline переключить GIN_MODE=release.
